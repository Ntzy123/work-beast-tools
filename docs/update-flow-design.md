# UniApp Android 应用内更新开发流程文档（浏览器跳转版）

**项目基础**：本文档适用于基于 UniApp 框架开发的 Android 应用，采用“浏览器跳转”方式实现应用更新。

## 1. 总体流程

1.  应用启动或用户进入设置页面时，触发版本检测。
2.  客户端获取本地版本号，向服务端版本检测接口发起请求。
3.  服务端返回最新版本信息，包含 `versionCode`、下载地址等。
4.  客户端比较本地 `versionCode` 与服务端 `versionCode`：
    -   若本地版本不低于线上版本，无操作。
    -   若线上版本更高，根据更新类型弹出对话框。
5.  用户确认更新后，客户端调用系统能力打开浏览器，访问 APK 下载地址。
6.  浏览器下载 APK 文件，用户从系统通知或文件管理器中启动安装。

## 2. 服务端接口设计

-   **接口地址**：`GET /api/wbtools_version/latest`
-   **返回数据结构**：
    -   `versionCode`：整型数字，用于版本比对。
    -   `versionName`：字符串，展示给用户的版本号。
    -   `forceUpdate`：布尔值，标记是否强制更新。
    -   `updateDesc`：字符串，更新日志文本。
    -   `downloadUrl`：字符串，APK 直链或下载落地页地址。
    -   `createdAt`：字符串，创建时间，ISO 8601 格式
    -   `updatedAt`：字符串，最后更新时间，ISO 8601 格式
-   **适配设置页面要求**：
    -   在设置页面templates/settings.html里新增一个配置，WBTools Version，对应json里的键值名为wbtools_version。

## 3. 客户端实现流程

### 3.1 获取本地版本号

-   通过 UniApp 的 `plus.runtime.versionCode` 获取当前应用的整数版本号（用于比对）。
-   通过 `plus.runtime.version` 获取字符串版本号（用于界面显示）。

### 3.2 版本检测触发时机

-   **应用启动检测**：在 App.vue 的 `onLaunch` 或首页 `onLoad` 中静默调用检测逻辑。
-   **设置页面手动检测**：提供“检查更新”按钮，用户点击后执行检测。

### 3.3 更新提示对话框

-   **非强制更新**：显示“取消”和“立即更新”两个选项。
    -   “取消”：本次运行不再提醒。
    -   “立即更新”：执行浏览器跳转。
    -   “忽略该版本”：将当前线上版本号存入本地存储，该版本不再提示更新。
-   **强制更新**：仅显示“去更新”按钮，对话框不可通过返回键或点击外部关闭，用户只能选择更新。
-   对话框内容需展示 `updateDesc` 更新说明。

### 3.4 浏览器跳转执行

-   调用 `plus.runtime.openURL(downloadUrl)` 方法。
-   系统会使用默认浏览器打开链接，下载行为完全由浏览器接管，应用本身不监听下载进度。

### 3.5 忽略版本存储

-   当用户在非强制更新中选择“忽略该版本”时，将当前线上 `versionCode` 保存至本地存储（如 `uni.setStorageSync`）。
-   后续检测到版本号等于或低于该忽略值时，不再弹窗。

## 4. 安装阶段注意事项

-   通过浏览器下载的 APK 在安装时，Android 8.0 及以上系统会弹出“允许此来源安装应用”的权限请求，此步骤完全由系统控制，应用无法干预。
-   可在更新提示文案中增加简短引导，如“下载完成后请在通知栏点击完成安装”，但这不是技术实现的一部分，仅作为用户体验提示。

## 5. 模块化组织建议

项目可创建 `utils/update.js` 工具模块，对外暴露 `checkUpdate` 方法，内部封装：

-   请求版本接口。
-   版本号比对逻辑。
-   忽略版本判断。
-   弹出更新对话框。
-   浏览器跳转调用。

启动逻辑与设置页面通过引入该模块并调用 `checkUpdate` 完成集成，无需在业务代码中重复编写检测逻辑。
